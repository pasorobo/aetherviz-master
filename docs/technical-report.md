## 1. エグゼクティブサマリー

**AetherViz Master** は、Claude Code（CLI）の **Skill** として動作する、AI駆動型の教育コンテンツ生成ツールである。ユーザーが任意の教育トピック（例：「ニュートンの第二法則」「光合成」「三角関数」）を入力すると、Claude Code が `SKILL.md` の指示に従い、**Three.js による 3D 可視化** と **SVG による 2D 図表** を組み合わせた、完全自己完結型・ゼロ依存の単一HTMLファイルを生成する。

### 主要特徴

| 観点 | 内容 |
|------|------|
| 配信形式 | Claude Code Skill（ローカル実行型 LLM プロンプトテンプレート） |
| 出力形式 | 単一HTMLファイル（外部ファイル依存なし、CDNのみ） |
| 描画技術 | Three.js r134 + SVG (D3.js オプション) のハイブリッド |
| 動作対象 | モダンブラウザ (Chrome/Edge/Firefox/Safari) + WebGL |
| 入力 | 自然言語のトピック（中国語/英語自動判定） |
| 出力 | インタラクティブ3D教育Webページ |

このリポジトリは **コード資産ではなく "プロンプト資産"** が中心であり、`SKILL.md` という単一の Markdown ドキュメントが事実上の「ソースコード」として機能している。

## 2. プロジェクト概要

### 2.1 製品コンセプト

AetherViz Master は「**互动教育可视化建筑师**（インタラクティブ教育可視化建築家）」と自称し、抽象的な教育概念をブラウザ上で 60fps の流体的 3D 体験へと変換することを使命とする。本ツールが対象とする学習者・コンテンツ制作者層は以下を含む：

- **教師**: 授業用デモ教材を瞬時に作成
- **学生**: 抽象概念を視覚で理解
- **教育コンテンツ制作者**: プロトタイプ生成

### 2.2 提供価値

1. **ワンクリック生成**: トピック入力 → 自動的に 3D インタラクティブHTML
2. **自動学科識別**: 物理／化学／生物／数学／天文／プログラミングを判定し配色を切替
3. **ゼロ門檻**: プログラミング知識不要で即利用可能
4. **プロ品質**: Three.js + SVG ハイブリッドで 60fps 滑らか描画

### 2.3 サポート対象領域

| 領域 | 例題 |
|------|------|
| 物理 | ニュートン第二法則、等速運動、電磁誘導、相対論時間膨張、量子トンネル効果 |
| 化学 | 光合成、酸塩基中和、酸化還元反応、分子構造 |
| 生物 | DNA 複製、細胞呼吸、有糸分裂、遺伝法則 |
| 数学 | ピタゴラス定理、三角関数、正弦関数像、確率分布 |
| 天文 | 惑星運動法則、宇宙膨張、ブラックホール、日食月食 |
| プログラミング | アルゴリズム計算量、データ構造、ソートアルゴリズム、デザインパターン |

### 4.2 ハイブリッド描画レイヤー設計

`SKILL.md` の中で定義されている重要なアーキテクチャの一つが、Three.js（WebGL）と SVG の **2 層合成** である：

```javascript
// 1. Three.js 3D シーン (底層)
const scene = new THREE.Scene();
const renderer = new THREE.WebGLRenderer({ alpha: true });

// 2. SVG オーバーレイ (上層、透明背景)
const svgContainer = document.createElement('div');
svgContainer.style.cssText = 'position:absolute;top:0;left:0;width:100%;height:100%;pointer-events:none;';
document.getElementById('canvas-container').appendChild(svgContainer);

// 3. 座標同期 (3D → 2D 投影)
function syncSVGto3D() {
    const vector = new THREE.Vector3(x, y, z);
    vector.project(camera);
    const sx = (vector.x * 0.5 + 0.5) * width;
    const sy = (-(vector.y * 0.5) + 0.5) * height;
    return { x: sx, y: sy };
}
```

**設計ポイント**:

- WebGL レンダラーは `alpha: true` で透過させる
- SVG レイヤーは `pointer-events: none` でマウスイベントを 3D シーンに透過
- `Vector3.project(camera)` で **NDC（正規化デバイス座標）** を計算し、ピクセル座標へ変換
- 結果として **3D オブジェクトの上に SVG ラベル / 矢印 / グラフを正確に重ね合わせ可能**

### 4.3 状態と再描画モデル

スライダー操作 → 状態更新 → 二重再描画 という単方向データフロー：

```
[Slider イベント]
        │
        ├──► Three.js オブジェクト属性更新 (position, scale 等)
        │
        └──► SVG path/d 属性 / 数値テキスト更新

[3D カメラ移動]
        │
        └──► SVG ラベル位置を projectVector で再計算

[window.resize]
        │
        ├──► renderer.setSize()
        │
        └──► svg.viewBox 更新
```

### 7.2 レンダリング方式判定

`SKILL.md:332-347` に明示された判定ロジック：

```javascript
function detectRenderMode(topic) {
    const threeKeywords = ['运动', '粒子', '碰撞', '旋转', '天体', '分子', '机械', '力', '磁场', '电场'];
    const svgKeywords    = ['函数', '图像', '曲线', '图表', '统计', '证明', '几何', '坐标'];
    const hybridKeywords = ['牛顿', '运动定律', '波动', '振动', '电磁', '能量'];

    const hasThree  = threeKeywords.some(k => topic.includes(k));
    const hasSVG    = svgKeywords.some(k => topic.includes(k));
    const hasHybrid = hybridKeywords.some(k => topic.includes(k));

    if (hasHybrid || (hasThree && hasSVG)) return 'hybrid';
    if (hasSVG) return 'svg';
    return 'three';
}
```

**特徴**:

- **キーワードベース**の決定論的アルゴリズム（LLM の不確実性に依存しない）
- ハイブリッドモードを優先（`hasHybrid || (hasThree && hasSVG)`）
- デフォルトは Three.js 純 3D
- 中国語キーワードのみ網羅されており、日本語・英語拡張の余地あり

### 7.3 言語検出

中国語/英語を自動判別し、生成 HTML 内の文言を適切な言語で出力する。

## 8. レンダリング方式の比較

### 8.1 三種類の方式

| 方式 | 用途 | 例 |
|------|------|----|
| **Three.js 純 3D** | 空間性・立体感が重要 | ニュートン運動、分子構造、惑星運動、粒子衝突 |
| **SVG 2D 図表** | 関数像、幾何証明、統計 | 三角関数、ピタゴラス定理、確率分布 |
| **Three.js + SVG ハイブリッド** | 3D + 数値図表の同時表示（推奨デフォルト） | 波動と振動、電磁波、エネルギー変換、力学解析 |

### 8.2 SVG 要素の使い分け

| 用途 | SVG 要素 | 例 |
|------|----------|----|
| 関数像 | `<path>` | 三角関数の波形 |
| 座標格子 | `<line>` | X/Y 軸 |
| データ図 | `<rect>`, `<circle>` | 棒グラフ、散布図 |
| 注釈矢印 | `<marker>` | 指示矢印 |
| 凡例 | `<g> + <text>` | 色分け凡例 |
| フローチャート | `<rect> + <path>` | ステップ図 |
| 目盛り | `<text>` | 軸目盛り数値 |

### 8.3 メリット・デメリット

**ハイブリッド方式の利点**:

- WebGL の高速 GPU 描画と SVG の鮮明なテキスト描画を両立
- SVG はベクター形式のため拡大時のジャギーがない
- グラフ要素を SVG に分離することで、Three.js のジオメトリを単純化できる

**ハイブリッド方式の課題**:

- 座標同期の計算コストが毎フレーム発生
- カメラ高速移動時に SVG 要素のフレーム遅延が目立つ可能性
- DOM 要素の数が増加（数百個以上の SVG ノードでパフォーマンス低下）

```
   → "牛顿" は hybridKeywords にマッチ → "hybrid"
        │
        ▼
[学科識別: 物理 → 青色テーマ]
        │
        ▼
[HTML 生成: Three.js 3D シーン + SVG 力学グラフ + KaTeX 公式]
        │
        ▼
[出力: <!DOCTYPE html> ... </html>]
        │
        ▼
[ユーザーがファイルを保存し、ブラウザで開く]
        │
        ▼
[インタラクティブ教材として動作]
```

## 11. 強み・弱みの評価

### 11.1 強み

| 項目 | 評価 |
|------|------|
| **革新性** | LLM 出力 + 単一HTML の組み合わせにより、教材制作の閾値を劇的に下げる |
| **再現性** | 出力規則の厳格な明文化で、LLM のばらつきを最小化 |
| **保守性** | 単一 `SKILL.md` を編集するだけで挙動を変更可能 |
| **配布性** | ゼロ依存 HTML のためメール/USB 等で容易に配布 |
| **教育設計** | 学習目標・公式・原理・応用を構造化したテンプレート設計 |
| **アクセシビリティ** | タッチ操作、レスポンシブ、KaTeX による数式可読性 |

### 11.2 弱み・リスク

| 項目 | 詳細 |
|------|------|
| **品質非決定性** | 最終的に LLM の生成精度に依存し、複雑な物理現象でバグ発生の可能性 |
| **検証手段の欠如** | リポジトリには **テストやサンプル出力ファイル** がなく、生成品質の検証手段が乏しい |
| **国際化不足** | キーワード検出が中国語のみ。日本語・英語トピックでは hybrid モード判定が効かない |
| **古い Three.js** | r134 (2021年) は古く、現行 r170+ と比較して性能・機能で劣位 |
| **アクセシビリティ非対応** | キーボード操作、スクリーンリーダー、`prefers-reduced-motion` の言及なし |
| **CDN 依存リスク** | オフライン環境や CDN 障害時に動作不能 |
| **セキュリティ** | `cdn.tailwindcss.com` は本番非推奨。SRI（Subresource Integrity）の指定なし |
| **ブラウザ互換性** | WebGL 必須。低スペック機・古いブラウザ非対応 |

## 12. 改善提案

### 12.1 短期改善（低コスト・高インパクト）

1. **テストハーネスの追加**
   - 代表的なトピック10種について、生成された HTML をリポジトリに保存
   - スクリーンショット差分テスト（Playwright + 視覚回帰テスト）

2. **多言語キーワード辞書化**
   ```javascript
   const i18nKeywords = {
     three: { zh: ['运动', '粒子'...], en: ['motion', 'particle'...], ja: ['運動', '粒子'...] },
     svg:   { zh: ['函数', '图像'...], en: ['function', 'graph'...], ja: ['関数', 'グラフ'...] },
     hybrid:{ zh: ['牛顿', '波动'...], en: ['Newton', 'wave'...],    ja: ['ニュートン', '波動'...] }
   };
   ```

3. **CDN 固定 + SRI**
   - SHA-384 ハッシュを `<script integrity="...">` で指定し、改竄検知

### 12.2 中期改善

4. **Three.js のバージョンアップ**
   - r134 → r170+ への移行。`BufferGeometryUtils` や `BatchedMesh` 等の最新機能を活用

5. **アクセシビリティ強化**
   - `aria-*` 属性の追加規約
   - `@media (prefers-reduced-motion: reduce)` で動画削減
   - キーボードショートカット規約

6. **オフラインモード**
   - CDN 依存ライブラリのバンドル版を `vendor/` に配置するオプション

### 12.3 長期改善

7. **生成結果ギャラリー**
   - GitHub Pages で代表的な生成例を公開
   - 各トピックのサムネイル + ライブデモ

8. **教育効果評価**
   - A/B テスト枠組み（既存教材 vs AetherViz 生成教材）

9. **ユニットテスト導入**
   - LLM 出力の構造的正当性を検証（valid HTML、必須要素の存在、KaTeX 数式の妥当性）

## 13. セキュリティと品質に関する考察

### 13.1 セキュリティ観点

- **入力サニタイズ**: ユーザーが入力するトピック文字列が HTML 内に直接展開される場合、LLM が XSS ベクトルを誤って混入させるリスクが理論上存在。`SKILL.md` には明示的なエスケープ要求がないため、追記推奨。
- **CDN 改竄**: 前述の通り SRI 未指定。教育機関で配布される場合、改竄された CDN によりマルウェア配布のリスクあり。
- **CSP 不足**: 生成 HTML に Content Security Policy ヘッダーやメタタグの言及なし。

### 13.2 品質観点

- **出力検証ループの欠如**: LLM が `</html>` で終わらない、KaTeX 構文エラー、Three.js の API 誤用などを犯した場合、自動検出する仕組みがない。
- **パフォーマンス保証**: 「60fps 滑らか」は願望であり、実機検証ループが存在しない。デバイスによっては低速化する可能性。

### 13.3 コンプライアンス観点

- **MIT ライセンス**: 商用利用可、明示的な著作権表示要求のみで非常に寛容
- **第三者著作物**: Three.js (MIT)、Tailwind (MIT)、KaTeX (MIT)、D3 (ISC) はすべて互換ライセンス

## 14. 結論

### 14.1 総合評価

AetherViz Master は **「LLM 駆動型教材ジェネレーター」というジャンルの実用的かつ洗練されたサンプル** である。`SKILL.md` の設計は、出力品質を担保する厳格な制約と、創造性を引き出す自由領域のバランスが取られており、Claude Code Skill エコシステムにおける **モデルケース** と評価できる。

### 14.2 主要な技術的貢献

1. **宣言的 HTML 生成パターン**: 単一 Markdown ファイルから複雑な単一HTML成果物を生成する手法の確立
2. **ハイブリッド描画**: Three.js (WebGL) と SVG の座標同期による、3D表現と2D図表の協調
3. **自動メタ判定**: キーワードベースの決定論的判定ロジックを LLM プロンプト内に埋め込む手法

### 14.3 推奨ロードマップ

| フェーズ | 目標 |
|---------|------|
| **Phase 1（〜1ヶ月）** | テストハーネス、多言語化、SRI 対応、サンプルギャラリー |
| **Phase 2（〜3ヶ月）** | Three.js r170+ 移行、アクセシビリティ準拠、オフライン版 |
| **Phase 3（〜6ヶ月）** | 教育効果計測、自動 QA パイプライン、コミュニティ拡大 |

### 14.4 まとめ

本プロジェクトは「コードを書かず、プロンプトを書く」という新たなソフトウェア開発パラダイムの実例として、教育分野で具体的なユースケースを実現している。少量のメタコード（`SKILL.md` 約 12KB）から、無限のバリエーションを持つインタラクティブ教材を派生させる **LLM 中心アーキテクチャ** の優れた事例である。今後は **品質保証の仕組み** と **国際化対応** を重点的に強化することで、グローバルな教育ツールへと飛躍し得る潜在能力を有している。
